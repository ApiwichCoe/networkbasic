OSI Model 7 Layers

OSI แบ่งการสื่อสารเป็น 7 ชั้น เพื่อให้รู้ว่าปัญหาเกิดที่ชั้นไหน เวลาส่งข้อมูลจะถูกห่อทีละชั้น (Encapsulation) และแกะออกตอนรับ การ Troubleshoot มักไล่จาก Layer 1 ขึ้นไป

Layerหน้าที่ตัวอย่าง
7 Applicationบริการที่ผู้ใช้เรียกใช้HTTP, DNS, DHCP
6 Presentationแปลงรูปแบบ / เข้ารหัสข้อมูลTLS, JPEG
5 Sessionเปิด-ปิดการเชื่อมต่อRPC, NetBIOS
4 Transportส่งข้อมูลระหว่างโปรแกรมด้วย PortTCP, UDP
3 Networkหาเส้นทางข้ามเครือข่ายด้วย IPRouter, IP
2 Data Linkส่งภายใน LAN ด้วย MAC AddressSwitch, VLAN
1 Physicalส่งสัญญาณไฟฟ้า / แสงสาย LAN, Fiber

อธิบาย OSI ทีละชั้น

Layer 7 - Application

จุดที่ผู้ใช้และโปรแกรมเรียกใช้เครือข่าย ไม่ใช่ตัวโปรแกรมเอง (เช่น Chrome) แต่คือโปรโตคอลที่โปรแกรมใช้ เช่น HTTP, DNS, DHCP, SMTP ข้อมูลที่ชั้นนี้เรียกว่า Data ปัญหาที่พบ: เข้าเว็บด้วยชื่อไม่ได้ (DNS), เว็บตอบ Error

HTTP, DNS, DHCP, SMTP

Layer 6 - Presentation

แปลงรูปแบบข้อมูลให้ทั้งสองฝั่งเข้าใจตรงกัน เช่น เข้ารหัส (TLS/SSL), บีบอัด, แปลงรหัสตัวอักษร (ASCII, Unicode) และรูปแบบไฟล์ภาพ (JPEG, PNG)

TLS, JPEG, Unicode

Layer 5 - Session

เปิด รักษา และปิด "เซสชัน" การคุยกันระหว่างสองโปรแกรม เช่น การ Login เข้าระบบหรือการเชื่อมต่อฐานข้อมูล ในโมเดล TCP/IP ชั้น 5-7 ถูกรวมเป็น Application ชั้นเดียว จึงมักไม่แยกพิจารณา

RPC, NetBIOS, SQL Session

Layer 4 - Transport

ส่งข้อมูลระหว่าง โปรแกรมกับโปรแกรม โดยใช้ Port ระบุปลายทาง TCP จับมือ 3 ทางก่อนส่ง, ใส่เลขลำดับ, รอ ACK และส่งซ้ำถ้าหาย ส่วน UDP ส่งไปเลยไม่รอยืนยัน ข้อมูลชั้นนี้เรียก Segment (TCP) / Datagram (UDP)

SYN → SYN-ACK → ACK

Layer 3 - Network

ระบุที่อยู่ด้วย IP และหาเส้นทางข้ามเครือข่ายด้วย Router ข้อมูลเรียก Packet มีค่า TTL ที่ลดลง 1 ทุกครั้งที่ผ่าน Router เมื่อเหลือ 0 จะถูกทิ้ง เพื่อไม่ให้แพ็กเก็ตวนไม่รู้จบ (traceroute ใช้หลักการนี้)

IP, ICMP, OSPF

Layer 2 - Data Link

ส่งข้อมูลภายใน LAN ด้วย MAC Address (48 bit เขียนเป็นเลขฐาน 16 จำนวน 12 หลัก) ข้อมูลเรียก Frame มี FCS ท้ายเฟรมไว้ตรวจว่าข้อมูลเสียหายหรือไม่ Switch จะเรียนรู้ว่า MAC ไหนอยู่พอร์ตไหนเก็บไว้ใน MAC Address Table VLAN (802.1Q) ทำงานที่ชั้นนี้

Ethernet, ARP, VLAN, STP

Layer 1 - Physical

ส่ง Bit ในรูปสัญญาณไฟฟ้า แสง หรือคลื่นวิทยุ ครอบคลุมสาย ขั้วต่อ ความเร็ว (10/100/1000) และ Duplex ปัญหาที่พบ: สายหลุด/ผิดชนิด, Duplex Mismatch (ฝั่งหนึ่ง Full อีกฝั่ง Half ทำให้ช้าและมี Error)

UTP, Fiber, Hub
เมื่อ Troubleshoot: ถ้า ping ได้แต่เปิดเว็บไม่ได้ ปัญหามักอยู่ Layer 4-7 (Port ถูกบล็อกหรือ DNS) ถ้า ping IP ในเครือข่ายเดียวกันยังไม่ได้ ให้ตรวจ Layer 1-2 ก่อน (สาย, VLAN, MAC)

TCP/IP Model (4 ชั้น) เทียบกับ OSI

OSI เป็นโมเดลอ้างอิงที่ใช้เรียนรู้และไล่ปัญหา ส่วน TCP/IP คือโมเดลที่อินเทอร์เน็ตใช้งานจริง มี 4 ชั้น (บางตำราแยก Network Access เป็น Data Link กับ Physical จึงเป็น 5 ชั้น) แต่ละชั้นของ TCP/IP คือการรวมหลายชั้นของ OSI เข้าด้วยกัน

Encapsulation: ข้อมูลถูกห่อทีละชั้น

ฝั่งส่งจะเติม Header ของแต่ละชั้นเข้าไปทีละชั้นจากบนลงล่าง ฝั่งรับจะแกะออกจากล่างขึ้นบน (De-encapsulation)

ลำดับการห่อข้อมูล

Data
  → + TCP Header (Port ต้นทาง/ปลายทาง)    = Segment
  → + IP Header  (IP ต้นทาง/ปลายทาง)      = Packet
  → + Ethernet Header (MAC ต้นทาง/ปลายทาง) = Frame
  → แปลงเป็นสัญญาณไฟฟ้า / แสง             = Bits
จุดที่ควรจำ: ระหว่างทางที่ผ่าน Router IP ต้นทาง/ปลายทางไม่เปลี่ยน แต่ MAC จะถูกเปลี่ยนทุก Hop (MAC ปลายทางคือ Hop ถัดไป ไม่ใช่เครื่องปลายทางจริง) เพราะ MAC ใช้ได้เฉพาะใน LAN เดียวกัน

ARP, TCP/UDP, DHCP และ DNS

ARP

ใน LAN การส่งข้อมูลใช้ MAC Address แต่เรารู้แค่ IP เครื่องต้นทางจึง Broadcast ถามว่า "IP นี้ MAC อะไร" แล้วจำคำตอบไว้ใน ARP Table

arp -a

TCP vs UDP

TCP เชื่อถือได้ มีการจับมือก่อนส่ง (SYN → SYN-ACK → ACK) ใช้กับเว็บ, SSH ส่วน UDP เร็วแต่ไม่ตรวจว่าถึงหรือไม่ ใช้กับ DNS, VoIP, วิดีโอ

HTTP 80 | HTTPS 443 | SSH 22 | DNS 53 | DHCP 67/68

DHCP ทำงานอย่างไร

Client ที่เพิ่งต่อเครือข่ายยังไม่มี IP จึง Broadcast หา Server ได้รับ IP, Subnet Mask, Gateway และ DNS กลับมาเป็นชุดเดียว ถ้าเครื่องได้ IP ขึ้นต้น 169.254.x.x แปลว่าติดต่อ DHCP Server ไม่ได้

ipconfig /renew

DNS ทำงานอย่างไร

เมื่อพิมพ์ชื่อเว็บ เครื่องจะถาม DNS Server (Port 53) เพื่อขอ IP ก่อนค่อยเชื่อมต่อ ถ้า ping IP ได้แต่ ping ชื่อไม่ได้ แสดงว่าปัญหาอยู่ที่ DNS

nslookup google.com

Router ตัดสินใจเลือกเส้นทางอย่างไร

Router ดู Destination IP ของแพ็กเก็ต แล้วเทียบกับ Routing Table โดยเลือกรายการที่ Prefix ตรงและ ยาวที่สุด (Longest Prefix Match) เช่น มี 10.0.0.0/8 และ 10.1.1.0/24 ปลายทาง 10.1.1.5 จะใช้ /24 ถ้าไม่เจอเลยจะใช้ Default Route (0.0.0.0/0) หรือทิ้งแพ็กเก็ต

ถ้ามีหลายโปรโตคอลรู้จักเครือข่ายเดียวกัน Router จะเชื่อค่า Administrative Distance (AD) ที่ต่ำกว่า: Connected = 0, Static = 1, EIGRP = 90, OSPF = 110, RIP = 120

! Default Route: ส่งทุกอย่างที่ไม่รู้จักไปทางนี้ (มักชี้ไป ISP)

OSPF

OSPF เป็น Dynamic Routing แบบ Link-State Router แต่ละตัวแลกเปลี่ยนข้อมูลลิงก์จนทุกตัวมีแผนที่เครือข่ายเหมือนกัน แล้วคำนวณเส้นทางที่ Cost ต่ำสุด (Cost มาจากความเร็วลิงก์) Area 0 คือ Backbone ที่ทุก Area ต้องเชื่อมถึง

Wildcard Mask คือค่าตรงข้ามของ Subnet Mask เช่น 255.255.255.252 → 0.0.0.3 และ 255.255.255.0 → 0.0.0.255 (bit 0 = ต้องตรง, bit 1 = ไม่สนใจ)

เงื่อนไขที่ Router จะเป็น Neighbor กัน: อยู่ Area เดียวกัน, Subnet เดียวกันบนลิงก์, Hello/Dead Timer ตรงกัน, Router ID ไม่ซ้ำ
สถานะที่ควรเห็น: Down → Init → 2-Way → ExStart → Exchange → Loading → Full (ใช้ show ip ospf neighbor ตรวจ ถ้าค้างที่ Init หรือ ExStart ให้ตรวจ Timer และ MTU)
ดู Route ที่ได้จาก OSPF: show ip route ospf

กำหนดค่า AD ของ Route สำรองให้สูงกว่า Route หลัก Router จะใช้ Route หลักตามปกติ และสลับมาใช้ Route สำรองเมื่อ Route หลักหายไป

แปลผล ping: Request timed out = ไม่มีคำตอบ (เช่น ปลายทางปิดหรือ ACL ตัด ICMP), Destination host unreachable = Router ไม่รู้เส้นทาง
ping IP ได้แต่ชื่อเว็บไม่ได้ = ปัญหา DNS

กรณีศึกษา: ไล่ปัญหาทีละขั้น

PC ได้ IP ขึ้นต้น 169.254.x.x (ไม่ได้ IP จาก DHCP)

ไล่ตรวจตามลำดับ:

  1. ตรวจสายและไฟ Link ของพอร์ต (show ip interface brief)
  2. ตรวจว่าพอร์ตอยู่ VLAN ถูกต้อง (show vlan brief)
  3. ตรวจว่า DHCP Server ถึงได้ (ลอง ping จาก Switch/Router ที่ Subnet เดียวกัน)
  4. ถ้า DHCP Server อยู่ต่าง VLAN ตรวจว่ามี ip helper-address บน Gateway
  5. ดูว่า Pool หมดหรือไม่ (show ip dhcp binding และ show ip dhcp pool)

สาเหตุที่พบบ่อย: อยู่ผิด VLAN, Pool เต็ม, ลืม Relay, Trunk ไม่ allow VLAN นั้น

ใช้งานภายในได้ แต่ออกอินเทอร์เน็ตไม่ได้

ไล่ตรวจตามลำดับ:

  1. ping Default Gateway ได้หรือไม่ (ถ้าไม่ได้ ย้อนไปดู Layer 1-3 ภายใน)
  2. ping 8.8.8.8 (IP ตรง ๆ) ได้หรือไม่
  3. ถ้า ping IP ไม่ได้: ตรวจ Default Route (show ip route | include 0.0.0.0), NAT (show ip nat translations) และสาย/ลิงก์ ISP
  4. ถ้า ping IP ได้แต่เปิดชื่อเว็บไม่ได้: ปัญหา DNS ตรวจ DNS ที่เครื่องได้รับ (nslookup google.com)
  5. ตรวจ ACL ที่อาจบล็อกขาออก

สาเหตุที่พบบ่อย: ไม่มี Default Route, ลืมกำหนด ip nat inside/outside, ACL ของ NAT ไม่ครอบคลุม Subnet, DNS ผิด

VLAN เดียวกันแต่อยู่คนละ Switch คุยกันไม่ได้

ไล่ตรวจตามลำดับ:

  1. ตรวจว่ามี VLAN นั้นอยู่ในทั้งสอง Switch (show vlan brief)
  2. ตรวจพอร์ตของ PC ว่าเป็น access และอยู่ VLAN ถูกต้อง
  3. ตรวจ Trunk (show interfaces trunk): VLAN ต้องอยู่ใน Allowed และ Active
  4. ตรวจว่าทั้งสองฝั่งเป็น Trunk และ Native VLAN ตรงกัน
  5. ตรวจ IP/Mask ของ PC ว่าอยู่ Subnet เดียวกัน

สาเหตุที่พบบ่อย: ลืมสร้าง VLAN บน Switch อีกตัว, Trunk ไม่ allow VLAN, ปลายหนึ่ง Trunk อีกปลาย Access

OSPF Neighbor ไม่ขึ้น หรือค้างที่ Init / ExStart

ไล่ตรวจตามลำดับ:

  1. ping ถึงกันได้บนลิงก์หรือไม่ (Layer 1-3)
  2. Subnet และ Mask ของลิงก์ตรงกันหรือไม่
  3. Area ตรงกัน และ network ครอบคลุม Interface นั้นจริง (show ip ospf interface brief)
  4. Hello/Dead Timer ตรงกัน และไม่มี ACL บล็อก OSPF
  5. Router ID ไม่ซ้ำ และไม่ได้ตั้ง passive-interface บนลิงก์ที่ต้องคุยกัน
  6. ถ้าค้าง ExStart/Exchange ให้ตรวจ MTU ของสองฝั่ง

สาเหตุที่พบบ่อย: Mask ไม่ตรง, Area ไม่ตรง, Router ID ซ้ำ, passive-interface ผิดพอร์ต, MTU ไม่ตรง

LAB 01 · Basic Network (PC → Switch → PC)

เป้าหมาย: ให้ PC สองเครื่องใน Subnet เดียวกันคุยกันผ่าน Switch และเห็นว่า Switch เรียน MAC เอง

Topology: PC1 และ PC2 ต่อ Switch ตัวเดียว (ไม่ต้องตั้งค่า Switch)

แผน IP: PC1 = 192.168.10.10/24, PC2 = 192.168.10.20/24

ตั้งค่าบน PC (Windows)

ตั้ง IP ที่ Network Adapter หรือใน Packet Tracer ที่แท็บ Config
ping 192.168.10.20

ตรวจผล: ping ได้รับ Reply (ครั้งแรกอาจ Timeout 1 ครั้งเพราะต้องทำ ARP ก่อน) บน Switch สั่ง show mac address-table จะเห็น MAC ของทั้งสองเครื่องและพอร์ตที่เรียนมา และบน PC สั่ง arp -a เพื่อดู ARP Table

LAB 02 · VLAN + Trunk

เป้าหมาย: แยก VLAN 10 / VLAN 20 และให้ VLAN เดียวกันคุยกันข้าม Switch สองตัวผ่าน Trunk

Topology: SW1 และ SW2 ต่อกันด้วยพอร์ต Gi0/24 (Trunk) แต่ละ Switch มี PC อย่างละ 2 เครื่อง (PC1, PC3 ใน VLAN 10; PC2, PC4 ใน VLAN 20)

แผน IP: VLAN 10 = 192.168.10.0/24 (PC1 .11, PC3 .13), VLAN 20 = 192.168.20.0/24 (PC2 .12, PC4 .14)

ตั้งค่า SW1 และ SW2 (เหมือนกัน เปลี่ยนพอร์ตตาม PC ที่ต่อ)

vlan 10

vlan 20

interface gigabitEthernet 0/1

interface gigabitEthernet 0/2

Topology: ต่อยอด Lab 02: เพิ่ม Router ต่อกับ Switch ผ่านพอร์ต Trunk (Switch Gi0/23 ↔ Router Gi0/0)

Switch - ตั้งพอร์ตที่ต่อ Router เป็น Trunk

interface gigabitEthernet 0/0

interface gigabitEthernet 0/0.10

interface gigabitEthernet 0/0.20
